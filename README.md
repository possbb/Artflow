# ArtFlow 游戏美术生产中台

本地优先的游戏美术 AI 素材规划与生成规则管理页面。

## 在线演示

GitHub Pages：<https://possbb.github.io/Artflow/>

在线演示可浏览全部规划页面并编辑模块要求，修改内容仅保存在当前浏览器。GitHub Pages 不运行本项目的 Express、FFmpeg 和本地文件存储服务，因此项目创建、图片上传、序列帧生成、资产入库与版本流转等完整生产功能需要按下方说明在本地运行。

## 当前功能

- 两个游戏设计上游模块：玩法设计记录产品定位、世界观、资产范围与目标平台；详细玩法设计继续维护游戏状态、输入动作、循环流程、战斗技能、多人协作、关卡遭遇、成长经济及异常验收细则。
- 九个美术生产模块总览，以项目级主视觉设计统一约束角色、技能、场景、UI与剧情关卡；主视觉读取玩法设计中的当前项目事实。
- 剧情关卡设计作为关卡美术父模块，背景设计和背景地图元素设计作为其下可独立编辑、管理素材的功能模块。
- 支持自主创建、切换和删除项目；创建时可选择已有文件夹作为存放位置，平台会在其中创建隔离的项目专属美术素材目录。
- 当前项目图片素材库支持按模块上传、预览、筛选和删除。
- 项目级资产注册中心统一管理逻辑资产、v1/v2 版本、正式版本指针和草稿/审核中/已确认/已废弃状态。
- 图片上传和“保存到已完成动作/动效”会自动注册资产；旧 manifest 会在首次打开注册中心时登记为 v1，不移动原文件。
- 支持角色、技能、关卡、UI、场景等对象关联，以及命名、格式、大小、尺寸、序列帧率和帧数自动校验。
- 玩法、主视觉、角色、技能、剧情关卡等上游模块变更会标记受影响的下游资产，支持人工复核或创建下一版本解决影响。
- 项目级技术美术规范可版本化维护 Godot 资源结构、导入/预制体、材质 Shader、骨骼蒙皮、动画压缩和粒子性能预算。
- 每个模块独立详情页。
- 内置产出物、制作规格、生成约束和验收门禁；各模块的美术设计要求直接作为 AI 生成依据。
- 要求分组可新增、编辑、删除和恢复默认。
- 修改内容自动保存到浏览器本地存储。
- 角色动作和技能动效支持上传视频，使用 FFmpeg 生成 PNG 序列帧并保存到项目。
- 桌面端和移动端响应式布局。

## 本地运行

```powershell
npm install
npm run dev
```

打开 `http://127.0.0.1:4173/`。也可以通过 `npm run build` 生成生产构建。

开发命令会同时启动页面 `http://127.0.0.1:4173/` 和本地项目服务。项目配置保存在 `project-data/projects/<项目ID>/`，包括 `modules.json`、`asset-registry.json`、`technical-standards.json` 和证据目录；图片素材、原视频、PNG 序列帧、manifest 与正式运行时资产保存在所选位置下由平台创建的 `ArtFlow/<项目名-ID>/` 专属目录。现有默认项目继续兼容原来的内部目录。运行序列帧功能前需要确保系统可以执行 `ffmpeg` 和 `ffprobe`。

## 数据说明

默认模块内容位于 `src/data/modules.ts`。手动修改保存到当前项目的 `modules.json`；浏览器仅记录上次打开的项目 ID，不再把不同项目的配置混在一起。资产注册表只引用既有源文件和运行时文件路径，删除物理素材时会保留已废弃的版本历史记录。删除使用外部素材目录的项目时，平台配置会被删除，但外部素材文件夹会保留，防止误删用户选择的目录。

`project-data/projects/*` 属于本机项目数据，默认不会提交到 GitHub；仓库仅保留空目录占位文件，避免公开上传未发布素材、原视频和运行时资产。
